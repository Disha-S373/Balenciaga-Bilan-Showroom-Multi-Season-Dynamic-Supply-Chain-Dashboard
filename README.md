# BAL_BILAN — Multi-Season Order Book Dashboard (Power BI)

A self-initiated Power BI dashboard built during my Supply Chain Analytics & Newness Planning
internship at a luxury fashion house, consolidating four seasons of pre-production
order data into a single interactive reporting tool — replacing a manual,
spreadsheet-only reconciliation process.

> **Note on data:** This repo contains no proprietary company data. The DAX and
> Power Query samples below use genericized table/column names and a synthetic
> shape (same structure and logic, invented codes/quantities/config values).

---

## The problem

Each season, the planning cycle produces two versions of the same order book at
different points in time — a pre-activities extract (orders as placed by sales
teams) and a post-activities extract (the same orders after cancellations, code
changes, and quantity adjustments have been pushed into the ERP system).
Comparing the two — and tracking milestones, deadlines, and product-level status —
was done by hand in Excel every season, with no persistent cross-season view.

## What I built

**Data model**
- A multi-season semantic model (4 seasons) consolidating pre- and post-activities
  extracts into one Power BI dataset
- Season-over-season comparison logic, matching line items between extracts
  (including across code changes, where an item's identifier changes between
  snapshots) and flagging status: matched / code-changed / dropped / newly added
- Config tables (key/value pairs) so page content — deadlines, objectives,
  milestone dates — can be updated season to season without touching any DAX

**Custom HTML/CSS visuals, driven entirely by DAX**

Native Power BI visuals can't render a milestone stepper, a styled calendar grid,
or a responsive product card grid — so I used the community "HTML Content" custom
visual and wrote DAX measures that generate complete, styled HTML documents at
query time:

- A **milestone timeline page**: a vertical stepper (on-time vs. late, connector
  lines, inline notes) built with `CONCATENATEX` iterating a milestones table,
  plus a rendered event calendar, both wrapped in inline CSS inside the measure
  itself — see [`dax/html-generation.dax`](dax/html-generation.dax)
- A **product catalogue grid**: one styled card per SKU (image, code, description,
  category, channel quantities, feedback status), laid out with CSS grid, entirely
  generated by a single measure iterating the order table row by row
- Both are config-driven, so re-pointing the model at a new season's data
  regenerates the whole page with no manual rebuild

**Standard DAX measures** — cancellation rate and value-at-risk by channel,
category-level wholesale exposure, MOQ-threshold flags, served-from-stock volumes
— see [`dax/measures.dax`](dax/measures.dax)

**Power Query (M)** — folder-based multi-file ingestion with sheet-type filtering,
whitespace normalization on status fields, code-change-aware matching keys, and
season-label standardization — see
[`power-query/transformations.m`](power-query/transformations.m)

**Python (pandas)** — pre-load consolidation and validation: aggregating each
season's raw extract to one row per item, and building the pre/post-activities
comparison (match-key fallback on code changes, status flagging, delta
calculations) before either file goes anywhere near Power BI — see
[`python/consolidation.py`](python/consolidation.py)

**Report pages**: order book catalogue, cancellation deep-dive, season timeline /
milestone tracker, season-comparison summary

## How it replaced the manual workflow

| Before | After |
|---|---|
| Manual VLOOKUP/pivot comparison per season in Excel | Automated match logic in Power Query, re-run each season |
| No cross-season view — each season's file was standalone | Single model, filterable by season |
| Milestone/deadline tracking in a static slide or doc | Live HTML timeline page, driven by a config table |
| Product catalogue built and re-styled by hand each season | One DAX measure regenerates the full card grid from config + data |
| Refresh = re-doing the analysis from scratch | Refresh = re-run the same pipeline on new source files |

## Tech stack

- **Power BI Service** (web) — Power Query (M), DAX, custom visuals (HTML Content
  by Subhro Bhattacherjee, Smart Filter Pro by OKViz)
- **Python / openpyxl / pandas** — source file consolidation and structural
  validation before load
- **Excel** — source system extracts (ERP order data)
